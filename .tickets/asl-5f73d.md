# Add apple.release-candidate-inspection with exact version and attached-build selection

## Goal
Deliver `apple.release-candidate-inspection`, a read-only, bounded App Store Connect workflow that resolves one exact bundle ID and exact IOS marketing version, then inspects only the build attached to that version. Authority: Steve's 2026-10-28 direction authorizes this recommended contained workflow and implementation/iteration; this investigation-backed ticket settles the slice without requiring a new package or plan. A successful inspection reports identities and provider states, never full submission readiness; all evidence delivered here is synthetic/offline and live authenticated Apple execution remains unverified.

## Design
### Decision and evidence

Decided by recommendation: four sequential GETs; fixed IOS; exact case-sensitive bundle ID and marketing version; two-item maximum selection pages; no pagination traversal; no latest-build heuristic; external complete Bearer header; no token generation/storage. This is one provider addition within the existing corpus unit, not a new application, library package, CLI feature, or generic readiness engine. The 2026-10-28 active-backlog query `tkt query --grep 'Apple|release-candidate|App Store'` returned `[]`. Existing epic `asl-4e2e8` is explicitly the public-API first wave, so use the small Apple-specific epic.

Grounding at repository base `83986e6c6f70cbfb69e33466792572417ea6f251`:
- `manifest.yaml` (`nws.address-forecast`, `vsphere.cluster-infrastructure-assessment`), `docs/corpus/adding-specs.md` (Acceptance Bar), and `tests/README.md` (ordered requests, error codes, `assert`, `view_contains`, `forbidden_output`) define registration and offline evidence.
- `specs/nws/address-forecast.arazzo.yaml` (`sourceDescriptions`, qualified `operationId`, explicit JSON Pointers) supplies the canonical wiring shape.
- `specs/vsphere/cluster-infrastructure-assessment.arazzo.yaml` (`resolve-datacenter`, `resolve-cluster`) demonstrates exact selection and typed collection guards. `specs/vsphere/README.md` (Credentials, TLS and invocation boundary) supplies the literal environment-reference pattern. ### Exact request and selection contract

All operations target the fixed HTTPS origin `https://api.appstoreconnect.apple.com`, use `Accept: application/json` and explicit `Authorization: $inputs.authorization`, and have no body. Use qualified operation IDs under one local source named `apple`. Retain upstream operation IDs, paths, parameter names, schema types/optionality and enum values in the subset. Apple array query parameters use form/explode=false; express the single filter values and comma-separated fieldsets as scalar wire values supported by the CLI, and assert decoded query maps exactly in scenarios.

1. `resolve-app`: GET `/v1/apps`, operation `apps_getCollection`; query `filter[bundleId]=<bundle_id>`, `limit=2`, `fields[apps]=name,bundleId`. Source: [List apps](https://developer.apple.com/documentation/appstoreconnectapi/get-v1-apps), OpenAPI `paths./v1/apps.get`, `AppsResponse`, `App`.
2. `resolve-version`: GET `/v1/apps/{id}/appStoreVersions`, operation `apps_appStoreVersions_getToManyRelated`; `{id}` is the preceding response's app ID. Query `filter[platform]=IOS`, `filter[versionString]=<marketing_version>`, `limit=2`, `fields[appStoreVersions]=platform,versionString,appVersionState,releaseType`. Source: [List app store versions](https://developer.apple.com/documentation/appstoreconnectapi/get-v1-apps-_id_-appstoreversions), OpenAPI matching path, `AppStoreVersionsResponse`, `AppStoreVersion`, `AppVersionState`. No state filter, sorting, include, or other page query. `appStoreState` is deprecated in 4.5.1; use `appVersionState`, with no legacy-field fallback.
3. `resolve-attached-build`: GET `/v1/appStoreVersions/{id}/relationships/build`, operation `appStoreVersions_build_getToOneRelationship`, empty query; `{id}` is the selected version ID. Require `data` object, `type=builds`, nonempty string ID. Source: [Get attached build ID](https://developer.apple.com/documentation/appstoreconnectapi/get-v1-appstoreversions-_id_-relationships-build), matching path and `AppStoreVersionBuildLinkageResponse`. This route identifies the version's attached build. The published response requires object `data` and does NOT mark it nullable; null/missing linkage is defensive failure coverage, not a claimed documented/live absence response. A 404 also fails. Never select another build if linkage is absent.
4. `inspect-build`: GET `/v1/builds/{id}`, operation `builds_getInstance`; `{id}` comes only from linkage `data.id`. Query `fields[builds]=version,uploadedDate,expirationDate,expired,processingState,usesNonExemptEncryption`. Require `data` object, `type=builds`, exact ID equality to linkage, nonempty string build `version`, and a documented `processingState`. Source: [Read build information](https://developer.apple.com/documentation/appstoreconnectapi/get-v1-builds-_id_), matching path and `Build`. `version` here is the build number, not the marketing version. Preserve the optional requested attributes when present; validate booleans as booleans and date fields as strings, without interpreting dates or computing readiness. Missing optional values remain absent and display as unknown.

Each step requires HTTP 200 and explicit `onFailure` type `end`. Selection success requires a genuine array `data` of exactly one object (not object-with-0-key or JSON-looking string), correct resource `type`, nonempty string `id`, exact returned `attributes.bundleId` or `attributes.versionString` equality, and IOS equality for version. Require attributes objects; version `appVersionState` must be a current documented enum value. Requiring identity/state fields is this workflow's inspection invariant, not a claim that Apple's optional attributes are globally required. Optional app name/releaseType must have their documented type/enum when present; absent values are unknown. Type checks must not rely only on regex over stringified JSON.

Both selection responses require a `links` object with string `self`, and no non-null `links.next`; reject even an empty string or malformed non-null next value. If `meta` exists it must be an object containing object `paging` with required `limit`; any present `paging.total` must be integer 1, and `paging.limit` must be a positive integer no greater than 2, and any non-null `paging.nextCursor` fails. Missing pagination metadata is permitted by the upstream optional schema. Reject duplicates, over-limit arrays, contradictory totals or any continuation indicator even when the first record matches. No cursor/next request is ever made. This proves unique selection only within the token-visible filtered response, not global account visibility. The four sequential reads are a point-in-time inspection, not an atomic snapshot or an assurance that attachment cannot change later.

### Authentication, failures, and presentation

Required inputs: `bundle_id` and `marketing_version` strings (nonempty, no comma-delimited multiple values; no defaults, normalization or version comparison); `authorization` string containing the externally supplied complete `Bearer ...` header, marked `writeOnly: true`, `format: password`, with no default. Fixed limit and platform are not inputs. Declare constraints and explicitly gate nonempty/comma-free selection inputs in the first bounded step before any downstream request because repository guidance warns that CLI 0.8.2 does not enforce every schema keyword. Wrong input types/missing required values fail via strict inputs. A syntactically bad string can cause at most the first capped app lookup; document this boundary rather than inventing a no-request validation guarantee.

Use env `APP_STORE_CONNECT_AUTHORIZATION` and document a missing-value shell guard plus the single-quoted whole reference `--input 'authorization=${APP_STORE_CONNECT_AUTHORIZATION}'`. The operator supplies the header externally; no signing, key IDs, issuer IDs, private keys, keychain, credential files, refresh, or login endpoint. Official [JWT authentication](https://developer.apple.com/documentation/appstoreconnectapi/generating-tokens-for-api-requests) requires a signed JWT in the Bearer header on each request. Do not assert a particular role guarantees all four calls; caller access/scope must authorize them, and 401/403 fail normally. Preview only with a synthetic sentinel; no trace/verbose guidance, credential outputs or auth-bearing URLs. All documented authenticated commands use `--strict-inputs --max-redirects 0`, trusted TLS, ordinary HTTP/execution/response-size limits, and no `--parallel`.

No matches, multiple matches, incomplete pages, invalid identity/type/state, absent attached build, mismatched returned build ID, and HTTP errors yield nonzero CLI `kind=error`; normal HTTP/criteria failures use `RUNTIME_SUCCESS_CRITERIA_FAILED` as in existing scenarios. Transport failures retain the CLI's actual transport error. Stop every later request. No synthetic success, partial-success report, fallback identity, retry (including 429/Retry-After), refresh, or arbitrary response URL fetch. Error output follows `arazzo-cli schema run` (`kind`, `error`, `code`), with no successful `outputs`; do not claim bespoke not-found/ambiguity codes or disclose raw error bodies/secrets. The view rejects every non-success envelope.

Conversely, a correctly inspected attached build with PROCESSING/FAILED/INVALID/VALID state or expired=true is a successful inspection. Display the reported values without translating VALID, expiry=false, an encryption flag, or a version state into submission eligibility. No review submissions, metadata/localizations/screenshots, pricing, agreements, export-compliance determination, TestFlight enrollment/visibility, uploads, publishing, writes, or full release readiness. No live authenticated Apple requests are part of implementation or acceptance.

Register manifest ID `apple.release-candidate-inspection`, provider `apple`, category `release-inspection`, workflow `release-candidate-inspection`, Arazzo 1.0.0, compatibility CLI 0.8.2+, `tier: dry-run`, `read_only: true`, `live_policy: manual-authenticated-read-only`, env above, local OpenAPI/scenario/view paths below. Quickstart previews `--step resolve-app` using synthetic input only; it cannot show downstream results. README covers discovery, show, strict validation, preview, authorized operator-only full run, `set -o pipefail`/`jq -er -f`, private ignored raw JSON artifacts, four-request maximum, non-atomicity, and source/provenance limits. Fixtures are explicitly synthetic contract-shaped examples; malformed cases are explicitly defensive. Summary and raw outputs are the same result contract, not separate selection logic.

### Inputs / Outputs

New additive corpus workflow surface only; existing workflows stay unchanged. On complete success, `.outputs` contains `selected_app` (the selected `/data/0` App resource), `selected_version` (selected `/data/0` AppStoreVersion resource), `attached_build_id` (linkage `/data/id`), and `build` (inspected `/data` Build resource). Preserve these raw JSON objects, including unknown response fields, with optional attributes absent when absent; do not copy credentials or entire unbounded envelopes into outputs. Schema-required `type`/`id` and workflow-required attributes remain visible. The summary labels app bundle ID/app ID, IOS marketing string/version ID/appVersionState, attached build ID/build number/processingState, expired, upload/expiration dates and usesNonExemptEncryption (unknown if absent), and says inspection does not establish submission readiness. App name and releaseType may be shown as optional context. There is no `ready`, `safe`, `eligible` or synthesized pass/fail release judgment. On failure there is only the existing CLI error envelope and no success output contract; distinguish failure reasons by the CLI's actual criterion/error text, without adding a custom application status system.
