# Resolve cluster assessment documentation gate

## Goal
Deliver the multi-resource cluster report using the documented scope Steve explicitly approved on2026-10-27: cluster configuration, resource-pool allocations, hosts and VM inventory. Storage/network enrichment is a separately gated follow-up.

## Design
Fixed authenticated chain using version8.0.3 documented Automation /api routes: POST session; GET datacenter list names filter -> unique datacenter; GET cluster list names and returned datacenter filter -> unique cluster summary HA/DRS; GET cluster/{id} -> name/resource_pool; GET resource-pool/{returned pool} -> childIDs and optional allocation configs; GET host list clusters=returned cluster; GET VM list clusters=returned cluster; DELETE session. Reuse VM-tested auth/header/unique-selection/failure cleanup conventions. Login has explicit failure:end; all other work failures goto distinct logout-failed which attempts DELETE and deliberately fails, preserving nonzero; normal logout ends success. No retry/partial success/live calls.
Expose selected datacenter/cluster/pool identities, cluster flags, pool config and children, full host/VM arrays, useful counts/configured CPU/memory summaries in jq, optional allocation absence unknown. No host-placement topology, runtime utilization/capacity estimate, datastore/network relationship claims. Cluster-scoped collection caps are explicit provider failure limits (hosts2500,VMs4000), no pagination/whole-estate substitute; CLI response/time bounds documented.
Use qualified local operations and session companion, safe .invalid server, tier dry-run manifest, complete synthetic scenarios; scope/identity guards reject malformed collection/object-shaped selectors. Arrays hosts/VMs may be empty valid; required fields in present entries must be valid by JSONPath where supported, no invented defaults. Basic absent downstream, session header exact, forbidden_output sentinels.
Provider guide full configure/run/preview commands names env credentials as existing tested pattern with redirects0, no live --step or traces; privileges/TLS/logout limits and explicit no real-vCenter validation. Versioned official cluster/resourcepool/host/VM URLs assessment own source contract. One reader report uses several APIs, not merely endpoint fetch.
