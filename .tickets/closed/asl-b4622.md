# Add safe vSphere endpoint configuration and session fixture support

## Goal
Establish the credential-free endpoint configuration and strict offline verification foundation for the three vSphere workflows authorized in the 2026-10-27 conversation and plans/current/vsphere-workflows.md.

## Design
Use existing corpus ownership: a new scripts/configure_vsphere.py owns only copying registered vSphere specs and their local OpenAPI companions into an explicit ignored output directory and rebasing top-level servers to a validated HTTPS origin. Expose --server and --output-dir; no execution, network calls, credentials, TLS weakening, overwrite of existing output, or changes to tracked sources. Validate scheme, hostname/optional port, absence of userinfo/path except optional root slash/query/fragment/placeholders; reject output inside source directories, root, existing entries and symlink/path escapes. Require registered local companions, qualified local operation IDs, no path/operation server overrides; preserve source-relative layout. Reuse check_entry where suitable without new runtime routing. Output the configured spec paths in a machine-readable JSON report (path IDs) without credentials. Decide by recommendation: this helper supplies the CLI0.8.2 server override that its run --help lacks.
scripts/fixture_server.py::match_request gains absent_headers assertions (case insensitive); its Handler sends no body for 204. scripts/verify.py::run_case gains optional expect.forbidden_output strings checked against captured stdout/stderr, with safe failure messages that do not print forbidden values. check_entry preflights types for new assertion fields; existing redirects and remote routing still rejected. tests/README.md documents these additive assertions.
Create shared session OpenAPI fixture documenting version8.0.3 POST /api/session (Basic header supplied explicitly;201 string) and DELETE /api/session (session header;204), safe .invalid server default, official URLs. specs/vsphere/README.md establishes prominent contract-based/synthetic/live-unverified notice plus endpoint configuration, credential env expansion guard, TLS limitations, no trace/no live step commands, redirects0, logout/failure/cancellation semantics. Do not claim workflow commands exist until each later slice lands.
Grounding: scripts/verify.py::check_entry/run_case and scripts/fixture_server.py::match_request/Handler; official session sources and CLI0.8.2 43-probe research recorded in plans/assessments/vsphere-contracts-2026-10-27.md. Root scripts own contributor utilities; tests own hermetic verification; provider directories own contracts/docs.
### File Impact
- Modify: scripts/fixture_server.py (absent-header assertions and bodyless204), scripts/verify.py (new safe assertion preflight/execution), tests/test_verifier.py (nearest harness tests), tests/README.md (scenario contract).
- Create: scripts/configure_vsphere.py (new file in existing scripts boundary; endpoint bundle configuration), tests/test_vsphere_configuration.py (helper behavior/security), fixtures/openapi/vsphere/session.yaml (shared session contract), specs/vsphere/README.md (provider pickup/limitations).
- Must not grow: scripts/verify.py must not own provider-specific workflow logic or relax local routing; sibling CLI must not change.

## Acceptance Criteria
- An explicit HTTPS origin produces a credential-free configured bundle of registered vSphere specs and companions, preserves layout, and changes only top-level server URLs; source bytes remain unchanged.
- Malformed origins, unsafe outputs, remote/unregistered/escaping sources and server overrides are rejected before publication of a usable bundle; no network calls or overwrites occur.
- Offline assertions can prove Basic is absent downstream, forbidden sentinel output is absent, and204 has no wire body, while existing external-routing safeguards remain enforced.
- Shared authentication contract and provider guide accurately document session behavior, supported setup and live-unverified evidence boundaries.
